Stage-Order Checker Spec v0.1

Author: AMU (perspective simulator, NOT canon authority). Status: PROPOSAL. Data label: Simulated. Never run on a live camera. Local only, nothing pushed (Publish HOLD + push hold). Neutral names only. No Avatar/Korra names, signs, moves, assets. Hover dropped (Metal S5 firewall). No bloodbending. No jumps. No harming. Research inputs (Oscar's 20 projects, Domawaye's 10 videos) are RESEARCH and not yet merged; section 9 lists what to fill from them.

1. Inputs

Per frame from pose tracker (33 landmarks if MediaPipe-style; any tracker with ankles, knees, hips, shoulders, elbows, wrists works): x,y,(z), visibility. Smooth with a short filter (e.g. 1-euro or 3-5 frame moving average). Drop frames with visibility < 0.5 for the joint.

2. Body links (the chain)

L1 feet/ankles -> L2 knees -> L3 hips (midpoint of hip landmarks) -> L4 trunk/spine (hip-to-shoulder-midpoint angle and height) -> L5 shoulders -> L6 elbows/wrists (hands). For each link compute speed s_i(t) (normalized by torso length so any body size/camera distance works) and find its peak time t_i = argmax speed within the move window.

3. Stage-order test

A move is a list of stages, each with: required links, a pose test, a timing window, and a hold requirement. Order score O = fraction of consecutive link pairs where t_(i+1) > t_i + min_gap (min_gap ~ 40-80 ms, PROPOSAL, untested). Perfect chain: t1 < t2 < t3 < t4 < t5 < t6. Arms-only wave: wrist peaks with no earlier hip peak -> O near 0 -> weak effect.

4. Score (0..1), all Simulated

  • O: order score (above), weight 0.45
  • S: smoothness = 1 - normalized jerk of the hip and wrist paths, weight 0.25
  • T: timing = how close each stage lands inside its window, weight 0.2
  • H: hold steadiness = low sway during required hold, weight 0.1 Effect size and calmness scale with the score. A low score still fires a small effect (never a hard fail), so slow or stiff players are not locked out. Weakest link = the pair with the largest order violation or timing miss; shown to the player ("your hips came late").

5. Stage templates for the proposed moves (neutral names)

  1. Stomp slab: plant -> load (knees+hips drop) -> drive (foot slam, hips lead) -> settle -> hold ~0.5s. Effect: slab rises. Cooldown.
  2. Low sweep: back foot push -> hip turn -> trunk -> trailing arm low. Effect: soft ground layer spreads along arm direction.
  3. Locked stance: feet plant wide -> hips brace -> spine/shoulders lock -> hold (length = firmness). Effect: slab firms up.
  4. Flow wave: feet shift -> hip circle -> trunk -> arm trails. Effect: water ribbon follows the hand; smoother circle = longer ribbon.
  5. Freeze hold: sharp stop in order hips -> trunk -> hand, then hold. Effect: ribbon turns to ice. (Holding still IS the pose.)
  6. Mist sweep: feet plant -> hips drop -> both arms wide and low. Effect: fog lifts; second hiding mechanic.
  7. Spin drift: feet pivot -> hips -> trunk -> arms trail; slow whole-body turn. Effect: soft wind in spin direction.
  8. Heal hold: slow breath, even stance, long smooth arm pass. Only move that rewards going slower. Effect: soft glow mends a cracked rock. Start with the ones already prototyped (1, then 3, 8) because they are the easiest to read on camera.

6. Chaining

Each move declares an end pose and a start pose. If end pose of A is within tolerance of start pose of B within a 1.5-2 s calm gap, the link counts as chained. Two clean links = combo bonus; no penalty for taking longer. A short balance beat between moves is required (safety). Level ladder (Simulated, PROPOSAL): L1 right pose; L2 right order; L3 right timing + calm finish; L4 two-move chain; L5 hold a stance while another move builds. Whether tiers map to Coach's Boy / Man / Mansa idea is UNKNOWN - Coach's call, not invented here.

7. Safety and honesty

No jumps at any level; slow tempo accepted; clear-space check; rest prompt every 5 min; camera stays on device, no recording or uploads. App says plainly: simulated game score, not training data, not fitness/medical advice. Never rewards harming anything or anyone.

8. Test plan (all Simulated)

a) Synthetic pose sequences: ideal chain, arms-only, reversed order, slow, jittery, missing joints. Expect O: ideal ~1, arms-only ~0, reversed low. b) Threshold sweep for min_gap, window widths, weights. Treat all numbers here as starting guesses, not measured. c) Only after Coach says yes in the 1:1: try on a real camera and record what actually breaks (occlusion, low light, frame rate on phones). Known risk: UNKNOWN whether a phone camera at 30 fps can read hip-before-shoulder gaps of ~50 ms reliably. If not, use stage order at coarser resolution (which link moved first within ~100-150 ms).

11. Update after Oscar's research file (RESEARCH; from his posted summary, bending-research-2026-10-28.md, not yet read line by line by AMU; licenses: only MIT/Apache items are build-safe, the rest idea-only)

  • Unit: measure in shoulder-widths (not torso length) and smooth landmarks; require position AND speed together; 2-second calibration at start (Sadball / IRLSurfer pattern).
  • Stage gates: each stage gets a minimum hold, a maximum time, a cooldown, and hysteresis (enter threshold differs from exit threshold) so it doesn't flicker. Idea from Meta's Interaction SDK; copy the idea, not the code.
  • Two scoring modes: (a) ordered chain (feet, waist, arms) for strikes/stomps; (b) "together" mode where hips and shoulders move as one for slow flow moves (flow wave, heal hold). Mode (b) scores sync and smoothness, not order.
  • Level 1 = hold the shape only (Tan Tui ladder: hold, then link smoothly, then add speed). This replaces my earlier "L1 right pose" wording; the rest of the ladder stays PROPOSAL.
  • Build order from Oscar: space check first, then locked stance, calm hold, stomp slab, two-arm sweep, hide-behind, stage-order chain, flow ribbon.
  • Conflict to resolve: Oscar says no spins; my template 7 (spin drift) is a slow whole-body turn. Mark spin drift DEFERRED until Coach says; nothing pushes toward the camera; targets are objects only, never people.
  • Hide-behind needs a person mask (segmenter) as well as pose; stage-order checker only needs pose.
  • Source gaps: about a dozen projects were README-only; Bending Sandbox licence statements conflict; Domawaye's video items 3 and 10 are low confidence.

  • Stage table (replaces sec. 2/3 link list for scoring): 0 Gate (shoulder-width in frame, full body visible, space clear) -> 1 Root (ankle/knee) -> 2 Hips -> 3 Torso -> 4 Arms -> 5 Settle (all velocities under a calm threshold, required to score). Score = order correct + timing in window + calm settle; never force.
  • Weight shift (my earlier stage 0) now lives inside Root. Gate is the real stage 0.
  • Levels follow the HOLD / LINK / SNAP teaching shape: Level 1 hold stages only (root, hips, settle); Level 2 LINK all stages slowly; Level 3 optional tighter timing. SNAP stays out of the early game.
